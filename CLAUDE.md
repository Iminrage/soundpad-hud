# CLAUDE.md

Soundpad HUD: Electron-приложение для Windows. Глобальный хоткей (Ctrl+Space) показывает прозрачный оверлей с emote-колесом, выбранный звук играет через удалённое управление Soundpad (named pipe `\\.\pipe\sp_remote_control`, RC 1.1.2). Пользователь: русскоязычный, UI и комментарии на русском.

## Команды

```bash
npm install
npm start            # электрон с окном настроек
npm run start:hidden # сразу в трей
npm test             # node --test, 51 тест, без Electron и без Soundpad
npm run probe        # сырые ответы живого Soundpad (Soundpad должен быть запущен)
```

Ярлык «Soundpad HUD» на рабочем столе запускает `node_modules\electron\dist\electron.exe .` в папке проекта (иконка `src/assets/icon.ico`). Закрытие окна прячет приложение в трей; чтобы подхватить новый код, нужен «Выход» в трее и повторный запуск.

Env `SOUNDPAD_PIPE` подменяет путь pipe (так работают тесты и probe).

## Архитектура

| Файл | Роль |
|---|---|
| `src/main/main.js` | жизненный цикл, окна, трей, IPC, подключение хуков к машине состояний |
| `src/main/soundpad.js` | клиент pipe: очередь запросов, сборка ответа, `DoPlaySoundFromCategory`, `DoPlaySound`, `GetCategories`... |
| `src/main/library.js` | XML в категории и звуки, псевдо-категория `all` («Все звуки», играется через `DoPlaySound(index)`), `relinkSlots` (поиск звука по пути файла, если индексы поплыли) |
| `src/main/hotkey.js` | чистая машина состояний хоткея: hold/toggle, автоповтор, запись комбинации |
| `src/main/selection.js` | виртуальный курсор и сектор по углу (0 сверху, по часовой) |
| `src/main/stats.js` | `PlayStats`: счёт проигрываний из колёс по пути файла, `stats.json` рядом с конфигом (запись с задержкой 1 с, `flush()` при выходе) |
| `src/main/config.js` | значения по умолчанию, валидация (`sanitize`), атомарная запись |
| `src/overlay/*` | колесо на SVG; получает от main `overlay:show / state / hide`; вне Electron работает в режиме предпросмотра |
| `src/settings/*` | окно настроек, общается через `window.api` (preload) |

Правила: CommonJS, без фреймворков и сборщиков; чистую логику держим отдельно от Electron, чтобы её можно было тестировать; рендереры ничего не знают о Soundpad и хуках, всё через IPC; пользовательские строки в DOM только через `textContent`.

Слот сектора: `{ catId: число | 'all' | null, pos, index, title, url, label, icon }`. `pos` это позиция внутри категории (с 1), которую ждёт `DoPlaySoundFromCategory`; для `'all'` играется глобальный `index`.

Листание страниц (конфиг v2): `source: { catId, name }`. При `catId: null` колесо показывает свои `slots`; иначе всю категорию по `sectors` звуков на страницу (`resolveSource`, `pageSlots`, `wrapPage` в `library.js`). Main держит `page` (помнит между открытиями, сбрасывает при смене источника) и `view` (что сейчас на колесе, из него играется выбранный сектор). Прокрутка uiohook `wheel` (`direction` 3, `rotation` > 0 вниз = следующая) по кругу шлёт оверлею `overlay:page`: секторы перерисовываются, выбор и точка остаются. Прокрутку не подавить, она доходит до игры. Если категорию переставили в Soundpad, при загрузке библиотеки источник находится по имени и id обновляется.

Хоткей: `{ ctrl, alt, shift, meta, keycode, name, modsOnly }`. `modsOnly: true` это комбинация только из модификаторов (минимум два, `keycode: null`): `HotkeyMachine` сам следит за зажатыми модификаторами (`_held`, потерянный keyup лечится флагами события), открывает колесо, когда зажат ровно нужный набор, а при записи фиксирует набор, когда отпущен первый модификатор. `keycode: null` без `modsOnly` означает «по умолчанию Space». Запись и открытие по Ctrl + Shift проверены вживую пользователем 2026-10-24.

Фокус (`grabFocus`, по умолчанию включён): на время показа колеса оверлей становится фокусируемым, перестаёт пропускать мышь (`setIgnoreMouseEvents(false)`) и забирает фокус (`show()` + `focus()`). Игра теряет фокус и не получает мышь, клики и прокрутку; это вариант без блокирующего хука, выбран ради античитов. После скрытия `releaseOverlay()` возвращает `focusable: false` и прозрачность для мыши, Windows сама отдаёт фокус окну под оверлеем. `blur` при открытом колесе отменяет выбор. Если Windows не дала забрать фокус, в `hud.log` пишется строка «оверлей не получил фокус». Выключено: старое поведение через `showInactive()`. Фокус вживую проверен пользователем 2026-10-24: работает, но курсор упирался в край экрана, а после закрытия игра видела сдвиг мыши.

Поэтому в режиме `grabFocus` оверлей ещё и захватывает указатель (Pointer Lock): main вызывает `window.lockPointer()` через `executeJavaScript(..., true)` (флаг жеста пользователя обязателен), рендерер шлёт `overlay:pointer-lock` и смещения `overlay:move` (`movementX/Y`, по возможности `unadjustedMovement`), main при захвате игнорирует `mousemove` из uiohook. На `overlay:hide` рендерер сразу делает `exitPointerLock()`, до возврата фокуса игре. Проверено вживую пользователем 2026-10-24: курсор не упирается в край, игра при закрытии не дёргается.

Возврат фокуса: явный возврат в запомненное окно через `koffi` (`GetForegroundWindow`/`SetForegroundWindow`) пробовали 2026-10-24 и откатили по решению пользователя: Windows и так отдаёт фокус окну под оверлеем, а приложение без лишней нативной зависимости легче. Не возвращать без просьбы. Если захват не включился, в `hud.log` строка «захват указателя не включился».

Колесо категорий (2026-10-24, вживую не проверено): второй хоткей `cfg.catHotkey` (формат как у `hotkey`, `null` — не задан; режим hold/toggle общий). `HotkeyMachine` перебирает `[['main', hotkey], ['cats', catHotkey]]`, `open` приходит с `{ id }`, закрывает колесо комбинация, которая его открыла (`active`); запись: `startRecording(target)`, `'recorded'` (combo, target). В main `wheelKind` ('main'/'cats') и `catOpen` (null — меню). Меню: непустые категории (`menuCategories`, `menuSlots`, слоты `folder`), снизу «Стоп», листается колесом мыши. ЛКМ (`navigate()`) открывает категорию или по «Назад» возвращает в меню, колесо при этом не закрывается; отпускание хоткея на папке или «Назад» ничего не играет. В открытой категории, пока Soundpad ничего не играет, снизу `backSlot()` вместо «Стопа»: main опрашивает `GetPlayStatus()` раз в 400 мс, пока открыто колесо категорий, и перерисовывает колесо без анимации (`overlay:page` с `flip: false`). Страницы хранятся отдельно: `pages.main`, `pages.menu`, `pages.cat`.

Подсказки под колесом (проверены вживую пользователем 2026-10-24): `#hints` в оверлее. Main кладёт в payload `ctx: { holding, stayOpen, canBack }`, оверлей в `hintItems(slot)` по типу выбранного сектора (центр, звук, «Стоп», папка, «Назад», пусто) собирает пары «клавиша — действие», а `hintGroups` группирует их по действию (по просьбе пользователя: сначала действие, потом все клавиши для него, без повторов) в порядке `ACTIONS`. Первой строкой обычным текстом идёт совет (`tipText`): что бинд можно отпустить (hold + stayOpen) или что клавиши можно отпустить (toggle); действия «Колесо останется» в строке действий нет. Галочки `showTips` и `showHints` (раздел «Вид колеса», по умолчанию включены) приходят в `ctx`. Колесо всегда по центру экрана, `#hints` висит под ним абсолютно и его размер колесо не двигает (раньше двигал, колесо «прыгало»); колесо `min(74vh, 86vw)`, чтобы панель помещалась на экране высотой 720. Над колесом так же висит `#fullname`: полное название выбранного звука или папки (`full` в payload: у звука `title` из Soundpad, у папки путь категории), всегда, пока выбран такой сектор (по просьбе пользователя); не больше двух строк. Название в центре колеса подгоняется по реальной ширине текста (`fitHub`, меряет невидимым `<text>` того же класса): до двух строк шрифтом 27 → 24 → 21 → 18 px, а если и 18 не влезает — первая строка начало, вторая «…» и конец (`fitPart`, режет по слову, если строка укоротится не больше чем вдвое). Подписи в самих секторах по-прежнему режутся `wrapLabel` с «…» на конце. Логика `hintItems` повторяет обработку в main (`mousedown`, `navigate`, `goBack`, `stayOpen`, toggle): меняешь одно — меняй и другое. Старое поле `hint` убрано, `sub` у папки теперь только «N зв.».

Клики в центре (мёртвая зона, `sel.selected === null`; проверено вживую пользователем 2026-10-24): ЛКМ закрывает колесо без звука; ПКМ делает `goBack()` (из открытой категории в меню колеса категорий), а если назад некуда — закрывает.

Предпрослушивание (вживую не проверено): зажатая ПКМ на звуке играет его с линиями `render: true, capture: false` (только в наушники), отпускание шлёт `DoStopSound()`. Если колесо закрылось с выбором звука, новый звук сам заменяет предпрослушивание; при отмене оно останавливается. Пока идёт предпрослушивание, статус «играет» не учитывается. Без `grabFocus` ПКМ доходит и до игры.

Значения по умолчанию (с 2026-10-24, по просьбе пользователя): колесо звуков Ctrl + Alt, колесо категорий Ctrl + Shift (оба `modsOnly`), `stayOpen: true`. Старые конфиги без `catHotkey`/`stayOpen` получают эти значения; `catHotkey: null` (бинд убран) и `stayOpen: false` сохраняются. Старый `hotkey` с `keycode: null` без `modsOnly` по-прежнему означает Ctrl + Space (`ensureHotkey`).

`stayOpen` (только для `mode: 'hold'`, вживую не проверено): при отпускании бинда `HotkeyMachine` спрашивает `missed()` (main: выбранный сектор не `isPlayable`, то есть не звук и не «Стоп»). Промах: колесо не закрывается, `machine.stuck = true`, событие `stuck`, дальше как в toggle (клик подтверждает, повтор бинда или Esc отменяют), подсказка в центре меняется на «Клик — сыграть». Это не то же, что режим toggle: попадание на звук при отпускании по-прежнему играет и закрывает.

«Частые» (проверено вживую пользователем 2026-10-24, как и сброс разделов): `playSlot` с `source: 'wheel'` после успешного ответа зовёт `stats.record(slot.url)`; прослушивание по ПКМ, тест из настроек и «Стоп» не считаются. `topCategory(stats.ranked(), library)` собирает псевдо-категорию из звуков «Всех звуков» (до 50, по убыванию счёта, при равенстве недавние): `id: ALL_ID`, чтобы играть через `DoPlaySound(index)`, и `menuId: TOP_ID`, под которым её открывает меню. В меню колеса категорий она первая, если есть хоть один найденный звук. В «Служебном» — счётчик и «Очистить» (IPC `stats:summary`, `stats:clear`); сброс раздела счёт не трогает. Собственный `playCount` Soundpad не используется: он считает и проигрывания из самого Soundpad и обновляется только с библиотекой.

Сброс настроек: у каждого раздела окна настроек кнопка «Сбросить» (`data-reset`). Поля разделов перечислены в `SECTIONS` (`config.js`), `resetPatch(section)` берёт их из `defaults()`, IPC `cfg:reset`; после сброса `ensureHotkey()` подставляет код Space вместо `keycode: null`. Новое поле настроек нужно добавить в один из `SECTIONS`, иначе упадёт тест. Сброс «Колеса звуков» спрашивает подтверждение.

Стоп-сектор: нижний сектор (`sectors / 2`, 0 сверху, по часовой) всегда «Стоп» (`DoStopSound()`), на любой странице и для своих секторов. `cfg.sectors` это всего секторов (чётное, 4–12), звуков на колесе `sectors - 1` (в настройках выбирается 3/5/7/9/11). `withStop` в `library.js` раскладывает звуки вокруг стопа; `cfg.slots[i]` это i-й звук, а не i-й сектор. Слот стопа: `{ stop: true, ... }`.
